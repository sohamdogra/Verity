# Verity — "Is this real?"

**An AI voice-scam shield for families.** HackGT 13 · Social Good track.

Scammers clone a loved one's voice from a few seconds of audio and call grandparents: *"I'm in trouble, please send money."* Verity helps adult children and their parents handle that moment.

> **Detection alone is an arms race. Families shouldn't have to depend on winning it — so we don't just detect, we verify.**

Verity has three layers, in priority order:

| Layer | What it does | Depends on AI? |
|---|---|---|
| **1. Verify** (core) | Family safe-word, 2–3 private challenge questions, trusted callback number | **No.** Works even against a perfect clone |
| **2. Detect** | Live audio → synthetic-likelihood *signal* (🟢 Low / 🟡 Elevated / 🔴 High concern) | Yes. Always shown as "a signal, not proof" |
| **3. Protect** | "Hang up and call them back using a number you trust." One-tap verify, call back, alert family | No |

If the model fails to download, the internet is down or detection breaks, Verity says **"Detection unavailable. Verification remains active."** and everything else keeps working.

**Check a recording** (`/check`) handles voicemails and voice notes. Upload any audio file (WAV, MP3, M4A, …) and Verity runs a multi-technique forensic analysis:
- 5 independent AI voice detectors
- WavLM speech embeddings
- signal forensics: digital silence, bandwidth, noise floor, prosody and splice checks
- a Whisper transcript checked for scam-script language

The same engine answers the **NSA HEARSAY challenge**. It is trained on the NSA data (LJ real speech + DiffSSD's 10 generators), selected by the challenge's own metric (ASVspoof5 minDCF, π_spoof = 0.3, C_fa = 4), and writes the official `filename<TAB>cm-score` TSV, also from a Docker image. See **[HEARSAY.md](HEARSAY.md)**.

## Quick start

Needs **Python 3.10+** and **Node 20+**. Commands are for Windows PowerShell; the macOS/Linux versions are in comments.

### Backend (FastAPI, port 8000)

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1                     # macOS/Linux: source .venv/bin/activate
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu   # CPU build (smaller)
pip install -r requirements.txt
uvicorn main:app --port 8000
```

- **First run downloads the detection model** (~360 MB, cached in `~/.cache/huggingface`) from HuggingFace in the background. The API is usable right away. `/health` reports `"detection_state": "loading"` until the model is ready, which takes about 30 s on a fast connection.
- **CUDA is optional.** If you have an NVIDIA GPU, install torch from the CUDA index instead (`--index-url https://download.pytorch.org/whl/cu124`). Verity picks the GPU automatically; `FORCE_CPU=1` turns that off. CPU is fine: one 2.5 s window takes ~0.15 s.

### Frontend (Next.js, port 3000)

```powershell
cd frontend
npm install
npm run dev          # or for the demo: npm run build; npm start
```

Open **http://localhost:3000**. Use `localhost`, not your LAN IP: browsers only allow the microphone on `localhost` or HTTPS.

### Demo checklist
1. **Family setup** (`/setup`): name, safe-word, trusted number, alert contact, 2–3 questions → the Family Shield card shows ✓ Protected.
2. **Live Shield** (`/`): play **Real voice** (stays 🟢), then **AI clone** (climbs to 🔴, showing the big "Hang up and call them back" banner and the three actions).
3. **Verify caller**: ask the challenge question and type a wrong answer → *"We couldn't verify this caller. Call them back using your trusted number."* Then the right answer → *"Verification succeeded."*
4. **Alert family** → confirmation page → **History** shows the timeline.
5. **Check a recording** (`/check`): upload an M4A/MP3 voicemail, or tap *AI voice clone*. The report shows each detector's verdict, the sound-forensics findings, the transcript with scam phrases highlighted, and a "For analysts" section with the 0–100 score.
6. The punchline: restart the backend with `DETECTOR_DISABLED=1` → "Detection unavailable. Verification remains active." Verification still works.

## Demo clips

The built-in clips live in `frontend/public/demo-clips/`. They're streamed through the real `POST /analyze` in 2.5 s windows while they play, just like mic audio. **No result is ever faked in the frontend.**

The repo ships **stand-ins** that mimic the real scam scenario, generated by `backend/scripts/devset/make_devset.py`:
- `real.wav`: a real person, LibriSpeech dev-clean speaker 1462 (CC BY 4.0)
- `clone.wav`: an **XTTS-v2 zero-shot clone of that same speaker** reading a "Mom, I'm in trouble, send money" script. This is the open-source equivalent of an ElevenLabs clone.
- `tts-legacy.wav`: old-style Windows text-to-speech (SAPI), for contrast

Neither clip is part of the training data, and the speaker is held out from training.

**Replacing them with your own voice and an ElevenLabs clone makes the demo even more convincing:**

1. **Record the real clip.** Record yourself (or a teammate *who consents*) reading a script such as: *"Hi Mom, it's me. I'm just calling to say I'll be home for dinner on Sunday."* Record 10–15 s in a quiet room. Phone voice memo or Audacity is fine.
2. **Make the clone.** In ElevenLabs → *Voices* → *Add a new voice* → *Instant Voice Clone*, upload 1–2 minutes of the **same person's** voice. (Only clone voices you have permission to clone.) Then use *Text to Speech* with that voice and a scam-style script: *"Mom, it's me, I'm in trouble and I need you to send money right now. Please don't tell Dad."*
3. **Export as WAV.** ElevenLabs usually downloads MP3. Convert both files to 16 kHz mono WAV:
   ```bash
   ffmpeg -i my_voice.m4a -ac 1 -ar 16000 real.wav
   ffmpeg -i elevenlabs.mp3 -ac 1 -ar 16000 clone.wav
   ```
4. **Drop them in** `frontend/public/demo-clips/` using the same names. No code change is needed; the titles are in `frontend/lib/demo-clips.ts`.
5. **Test through the app**, and also score them from the command line:
   ```powershell
   cd backend
   .\.venv\Scripts\python scripts\calibrate.py ..\frontend\public\demo-clips\real.wav ..\frontend\public\demo-clips\clone.wav
   ```
   It prints each window's raw and smoothed score, band and stability, so you can tune `BAND_GREEN_MAX` / `BAND_RED_MIN`.

You can also **upload any WAV** from the Live Shield page, or use **Start listening** with the call on speakerphone.

## Detection model: read this before the demo

Live Shield has two engines, chosen with `LIVE_DETECTOR` in `backend/.env`:

- **`hearsay`** (default): the trained live model in `backend/models/hearsay_live.joblib` (WavLM embeddings + signal features), scoring the last ~7.5 s of audio. Train it with `scripts/hearsay.py train --feature-set live` (see [HEARSAY.md](HEARSAY.md)). **If the file is missing, Verity falls back to `single` automatically.**
- **`single`**: one pretrained detector. The default is **`MelodyMachine/Deepfake-audio-detection-V2`**, with fallbacks `mo-thecreator/Deepfake-audio-detection` → `Bisher/wav2vec2_ASV_deepfake_audio_detection` (a Wav2Vec2 model trained on ASVspoof). Each is tried in order; a model whose labels can't be understood is skipped.

Pretrained detectors are brittle. On a real speaker vs an XTTS-v2 clone of that same speaker, none of them reliably flagged the clone (see HEARSAY.md). That's why the trained engine is the default.

We scored the stand-in clips (mean synthetic likelihood across 2.5 s windows):

| Model | real.wav (LibriSpeech) | clone.wav (Windows TTS) |
|---|---|---|
| MelodyMachine V2 (default) | 0.00 | **0.00 (misses it)** |
| mo-thecreator | 0.60 (flips 0↔1) | 0.83 |
| **Bisher ASV wav2vec2** | **0.00** | **0.84** (0.96–1.0 after the first window) |
| Hemgg | 0.43 (flips) | 0.98 |
| MattyB95 AST ASVspoof2019 | 1.00 | 1.00 |

Small open detectors are brittle and each generalizes to different kinds of fakes. That is exactly why Verity leads with verification. Old-style SAPI TTS is also not an ElevenLabs clone, so **run `calibrate.py --models` on your own clips and pick the model that separates them best**:

```powershell
.\.venv\Scripts\python scripts\calibrate.py --models MelodyMachine/Deepfake-audio-detection-V2,Bisher/wav2vec2_ASV_deepfake_audio_detection,mo-thecreator/Deepfake-audio-detection
```

Then set the winner in `backend/.env`:
```
DETECTOR_MODELS=Bisher/wav2vec2_ASV_deepfake_audio_detection
```

Labels are normalized in `backend/detection/labels.py`. Matching is case-insensitive and ignores label order, handling `fake/real`, `real/fake`, `Bonafide/Spoof`, `AIVoice/HumanVoice`, `spoof`, `synthetic`, `ai-generated` and so on. For opaque labels (`LABEL_0`), add a `label_overrides` entry in `backend/detection/models.py`.

## Architecture

```
Verity/
├── backend/                     FastAPI + SQLite + transformers
│   ├── main.py                  all endpoints
│   ├── config.py                ← every threshold & setting (bands, windows, rate limits)
│   ├── scoring.py               rolling 3-window smoothing, bands, stability
│   ├── audio_io.py              decode WAV → 16 kHz mono, windowing, silence gate
│   ├── security.py              normalize + PBKDF2-SHA256 hashing of secrets
│   ├── db.py                    sqlite3 schema & queries
│   ├── alerts.py                simulated alerts + optional webhook
│   ├── detection/
│   │   ├── detector.py          Detector.analyze(audio) → float  (model-agnostic, live path)
│   │   ├── labels.py            label normalization → synthetic_likelihood
│   │   ├── models.py            model registry / fallback order
│   │   └── registry.py          shared pipeline cache (each model loaded once)
│   ├── forensics/               "Check a recording" + HEARSAY engine
│   │   ├── analyzer.py          orchestrator: decode → choose techniques → fuse → explain
│   │   ├── decode.py            any format (soundfile, ffmpeg fallback) + metadata
│   │   ├── dsp.py               signal forensics (silence, bandwidth, noise, prosody, splices, MFCC)
│   │   ├── neural.py            5-detector ensemble + WavLM embeddings
│   │   ├── transcript.py        Whisper + scam-script cues
│   │   ├── fusion.py            trained bundle or default weighted fusion; manipulation type
│   │   ├── harmonize.py         make training audio match the test set; label-blind augmentation
│   │   ├── metadata.py          RIFF/tags/header/MAC-time container forensics (report only)
│   │   └── training.py          label parsing, feature cache, metrics
│   ├── models/                  hearsay.joblib (full model), hearsay_live.joblib (fast / Live Shield), metrics
│   ├── Dockerfile               HEARSAY inference image (scores /data -> /out/predictions.tsv)
│   ├── scripts/
│   │   ├── calibrate.py         score clips per window; compare models
│   │   ├── hearsay.py           HEARSAY extract / train / predict (submission TSV) / evaluate
│   │   ├── hearsay_prepare.py   harmonize + augment NSA training data to the test-set format
│   │   ├── devset/              build the labeled practice set (+ demo clips)
│   │   └── make_demo_clips.py   legacy stand-in clip generator
│   └── tests/                   label mapping, hashing, bands, decoding, fusion, labels CSV
└── frontend/                    Next.js 16 App Router + TS + Tailwind v4 + shadcn/ui
    ├── app/
    │   ├── page.tsx             /        Live Shield
    │   ├── setup/page.tsx       /setup   Family setup + Family Shield card
    │   ├── verify/page.tsx      /verify  challenge / safe-word verification
    │   ├── check/page.tsx       /check   forensic report for an uploaded recording
    │   ├── history/page.tsx     /history protection timeline
    │   └── alert/               /alert   alert confirmation
    ├── hooks/use-shield.ts      mic + clip capture → 2.5 s WAV windows → POST /analyze
    ├── lib/audio.ts             resample (OfflineAudioContext), WAV encoder
    ├── lib/api.ts               typed API client
    └── public/
        ├── worklets/capture-processor.js   AudioWorklet mic capture
        └── demo-clips/          real.wav, clone.wav, tts-legacy.wav
```

**Detection flow:** browser mic (AudioWorklet) or clip → cut into 2.5 s windows → resampled to 16 kHz mono → WAV → `POST /analyze` (multipart, with `session_id`). The backend skips silent windows, scores each window, keeps the last 3 per session, and returns the smoothed average, band and stability. Red needs at least 2 samples, so one odd window can reach amber but never red on its own. The first time a session turns red, a `suspicious_voice` event is logged.

**Bands** (on the smoothed score, set in `backend/config.py` and served via `/health`): green `< 0.40`, amber `0.40–0.65`, red `> 0.65`. The UI never shows percentages; only words, a meter and colored dots.

**Secrets:** safe-words and answers are normalized (lowercase, trimmed, punctuation dropped, spaces collapsed) and hashed with salted PBKDF2-SHA256. "Pizza Place!" matches "pizza place".

**Rate limiting:** 5 failed verification attempts → locked for 5 minutes, with a recommendation to call back. Tracked in the `verification_attempts` table.

## API

| Method | Path | Body | Returns |
|---|---|---|---|
| `GET` | `/health` | – | `{status, model, device, detection_available, detection_state, thresholds, …}` |
| `POST` | `/analyze` | multipart: `file` (WAV), `session_id`, optional `family_id` | `{synthetic_likelihood, smoothed, band, stability, samples, history, silent, model}`; **503** when detection is unavailable |
| `POST` | `/forensics` | multipart: `file` (any audio format), optional `family_id`, `transcribe` | `{synthetic_likelihood (0-100), prediction, band, manipulation_type, manipulation_label, techniques[], transcript, steps[], metadata, calibrated}` |
| `POST` | `/family` | `{id?, name, safe_word?, trusted_phone, alert_contact, challenges:[{id?, question, answer?}]}` | family (no secrets) |
| `GET` | `/family/{id}` | – | family |
| `GET` | `/family/current` | – | most recent family (single-family mode) |
| `POST` | `/verify` | `{family_id, method: "challenge"\|"safe_word", challenge_index, answer}` | `{passed, locked, attempts_remaining, locked_until, message}` |
| `POST` | `/alert` | `{family_id, reason?, band?, synthetic_likelihood?, notes?}` | `{event_id, delivery: simulated\|webhook\|webhook_failed, alert_contact, message}` |
| `POST` | `/events` | `{family_id, event_type: "callback_started"}` | event |
| `GET` | `/events/{family_id}` | – | events, newest first |

Interactive docs: http://localhost:8000/docs

```bash
curl -F file=@frontend/public/demo-clips/clone.wav -F session_id=test localhost:8000/analyze
```

## Environment variables

**`backend/.env`** (copy `backend/.env.example`; everything is optional)

| Variable | Default | Purpose |
|---|---|---|
| `LIVE_DETECTOR` | `hearsay` | `hearsay` = trained live model (falls back to `single` if missing); `single` = one pretrained detector |
| `HEARSAY_LIVE_MODEL_PATH` | `backend/models/hearsay_live.joblib` | Trained live model |
| `DETECTOR_MODELS` | built-in fallback list | Comma-separated HF model ids to try in order |
| `DETECTOR_DISABLED` | `0` | `1` = demo the "Detection unavailable" state |
| `FORCE_CPU` | `0` | Ignore CUDA |
| `ALERT_WEBHOOK_URL` | empty (simulated) | Discord/Slack webhook, Twilio proxy or any JSON endpoint |
| `BAND_GREEN_MAX` / `BAND_RED_MIN` | `0.40` / `0.65` | Band thresholds |
| `SILENCE_RMS` | `0.004` | Windows quieter than this aren't scored |
| `VERIFY_LOCK_SECONDS` | `300` | Lock length after 5 failed attempts |
| `DATABASE_PATH` | `backend/verity.db` | SQLite file |
| `CORS_ORIGINS` | `http://localhost:3000,http://127.0.0.1:3000` | Allowed frontend origins |
| `HF_HUB_OFFLINE` | – | `1` = never touch the network once the model is cached |
| `FORENSICS_DETECTORS` | 5 built-in models | Detector ensemble for `/forensics` and HEARSAY |
| `FORENSICS_EMBEDDING_MODEL` | `microsoft/wavlm-base-plus` | Embedding model for the trained fusion |
| `FORENSICS_ASR_MODEL` / `FORENSICS_ASR_DISABLED` | `openai/whisper-base.en` / `0` | Transcript + scam cues |
| `FORENSICS_WARMUP_DISABLED` | `0` | `1` = don't preload forensic models at startup (saves ~2 GB RAM) |
| `HEARSAY_MODEL_PATH` | `backend/models/hearsay.joblib` | Trained fusion bundle |
| `FFMPEG_PATH` | `ffmpeg` on PATH | Needed for M4A/AAC/OPUS/WEBM uploads |

**`frontend/.env.local`** (copy `frontend/.env.example`)

| Variable | Default |
|---|---|
| `NEXT_PUBLIC_API_URL` | `http://localhost:8000` |

**Webhooks:** Discord (`discord.com/api/webhooks/...`) gets `{"content": ...}`, Slack (`hooks.slack.com/...`) gets `{"text": ...}`, anything else gets `{"message", "family", "alert_contact", "reason", "band"}`. If the webhook fails, the alert is still logged in-app.

## Responsible design
- Verity never claims a voice **is** fake. The copy says "synthetic characteristics detected", and every result is framed as a signal, not proof.
- A low signal is never presented as "safe". The UI still recommends verifying any request for money.
- Verity does not tap phone calls. Audio comes from the device mic (speakerphone), an uploaded file or the built-in clips, and is analyzed in memory, never stored.
- Demo-grade security: there are no user accounts, and the API trusts whoever can reach it. Don't expose it to the internet as-is.

See **[DEBUGGING.md](DEBUGGING.md)** for known issues and fixes.
